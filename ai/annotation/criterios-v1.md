# O que "atende" exige em cada critério (checklist-v1)

Regra geral: **atende** quando o TCC *faz ou descreve* o item, não quando só
cita a palavra. Menção ao tema em outro sentido, intenção genérica ou
ausência declarada não atendem. **Contradiz** quando o texto afirma o oposto
do critério. **Não encontrado** em todos os outros casos.

| # | Atende quando | Não basta |
| --- | --- | --- |
| C1 | Declara o objetivo geral do projeto. | Objetivos de seções ou de outros trabalhos. |
| C2 | Explica o problema ou a necessidade que motiva o projeto. | Só contexto genérico da área, sem ligar ao projeto. |
| C3 | Cita trabalhos ou soluções existentes e os relaciona ou contrasta com a proposta. | Só citar fontes de dados ou estatísticas de mercado. |
| C4 | Nomeia tecnologias, linguagens, frameworks ou ferramentas usadas na implementação. | Tecnologias só citadas como alternativas. |
| C5 | Descreve componentes da solução e como se ligam (camadas, módulos, cliente-servidor). | Só listar tecnologias. |
| C6 | Descreve como o trabalho foi conduzido (etapas, método ágil, procedimento de pesquisa). | Só a palavra "metodologia" como título. |
| C7 | Apresenta números medidos do próprio trabalho (métricas, tempos, taxas, contagens de teste). | Números de contexto, de mercado ou de outros trabalhos. |
| C8 | Descreve teste ou avaliação feito com usuários reais (quem, como, resultado). | Testes técnicos de integração; questionário só para levantar requisitos. |
| C9 | Descreve testes automatizados executados (unitários, integração, ponta a ponta, ferramenta de teste). | Testes manuais; citar a falta de testes automatizados. |
| C10 | Descreve medidas adotadas de segurança ou proteção de dados (autenticação, criptografia, permissões, LGPD). | "Segurança" em outro sentido (física, no trânsito) ou como item desconsiderado. |
| C11 | Discute limitações da própria solução ou dos resultados. | Limitações de outras tecnologias ou do mercado. |
| C12 | Propõe trabalhos futuros concretos (o que seria feito depois). | Frase genérica de que o trabalho pode evoluir; requisitos atuais. |
| C13 | Informa que a solução está implantada em uso real, em produção. | Protótipo, piloto ou demonstração; nesses casos, contradiz se o texto disser que não foi implantada. |
| C14 | Apresenta estimativa de custos, orçamento ou análise de viabilidade financeira do projeto. | Citar custos do problema ou que algo é "de baixo custo". |
| C15 | Trata de acessibilidade para pessoas com deficiência ou de usabilidade inclusiva. | "Acessível" no sentido de alcançável, disponível na web ou acessibilidade urbana. |
| C16 | Descreve dados usados no trabalho (origem, conteúdo, tamanho), como base de treino, dados abertos ou corpus. | Só o banco de dados da aplicação ou seu esquema. |
